# Production backend contract

Run `uvicorn production.app:create_app --factory --host 127.0.0.1 --port 8790` after `alembic upgrade head`. All routes have `/api` prefix. PostgreSQL required; separate migration owner and runtime roles (`voicegen_api`, `voicegen_worker`). Runtime logins must be NOINHERIT/NOBYPASSRLS and members of the appropriate role; the application explicitly SET LOCAL ROLE. Never run runtime as database owner or superuser.

`POST /session {access_token: <Supabase access JWT>}` validates asymmetric RS256/ES256 JWT against configured issuer/audience/JWKS, exchanges for opaque Secure HttpOnly SameSite=Strict cookie, returns `{ok:true}`. `DELETE /session` revokes. Mutations require exact APP_ORIGIN. There is no owner-token fallback. Roles come from database only.

`AUTH_MODE=local` disables the JWT exchange. `POST /account {email,password}` creates a zero-balance account and session. `POST /account/session` logs in. Both set the same cookie. Passwords are PBKDF2-SHA256 and are never returned. Duplicate email returns 409. Wrong password returns 401. JWT login stays available when `AUTH_MODE` is unset.


`GET /health`, authenticated `GET /me` => `{user:{id,email},wallet:{balance,available,reserved,source:'application'}}`; `GET /voices` => `{voices:[],hasMore:false}` until verified supplier configured. `POST /generate` accepts existing TTS request shape (request_id mandatory), returns `{generation}`. `GET /history` => `{items}`, `GET /history/{id}` => `{generation}`; owned local IDs only. `GET|HEAD /audio/{id}` uses cookie, private streaming and byte ranges, expires 24 hours from submission; never public object URLs.

Manual payment flow: `POST /topups {request_id,amount,reference}` -> `{topup}`; `PUT /topups/{id}/evidence` raw PNG/JPEG/PDF (max 5 MiB); `GET /topups` lists own records. Admin `GET /admin/topups`, `GET /admin/topups/{id}/evidence`, `POST /admin/topups/{id}/approve {verification_reference}` requires an independent bank/processor reference, cannot approve own topup, no screenshot auto approval. Amounts are integer application credit units; a real payment-to-credit commercial policy remains deployment configuration/operational responsibility.

Required env: DATABASE_URL, SUPABASE_ISSUER, SUPABASE_AUDIENCE (default authenticated), SUPABASE_JWKS_URL, APP_ORIGIN (HTTPS). Public frontend auth configuration uses SUPABASE_URL and SUPABASE_ANON_KEY; only the publishable/anon key belongs there. `/health` exposes these public values under `auth: {provider:'supabase',url,anonKey}` and `mode:'production'`; it never exposes DB or supplier credentials. S3_ENDPOINT_URL/S3_BUCKET/S3_ACCESS_KEY_ID/S3_SECRET_ACCESS_KEY for private R2. CREDIT_PER_CHARACTER positive integer required for generation pricing. No default funded wallets. SUPPLIER_ENABLED stays false; GenMax adapter must remain disabled until upstream contract is independently verified. Worker uses WORKER_DATABASE_URL. Worker reservations remain held on unknown submission; administrators reconcile with immutable audit. `POST /admin/generations/{id}/reconcile {outcome:'failed'|'completed', verification_reference}` settles uncertain or expired pending reservations once and records immutable audit; self-reconciliation is denied. Expiry is an access deadline, not an object-deletion promise. Pending remote jobs that pass expiry retain their reservation until independent reconciliation; queued jobs that expire before dispatch are refunded safely.

Verification (disposable PostgreSQL only): `DATABASE_URL=<migration-owner-url> .venv/bin/alembic upgrade head`, `.venv/bin/python -m pytest tests/production -q`; the test bootstrap creates dedicated NOINHERIT/NOBYPASSRLS logins. `.venv/bin/python -m production.worker --once` exercises a worker cycle with WORKER_DATABASE_URL; the shipped supplier remains disabled. `.venv/bin/python -m production.import_sqlite /path/staging.sqlite --dry-run` produces a read-only inventory and raw numeric supplier audit manifest with zero customer credits; applying an account-mapping import is deliberately not implemented.

Historical local evidence, not rerun in this environment: PostgreSQL 16 migration downgrade-to-base and upgrade-to-head passed; 20 production tests passed, including RSA/EC JWKS, signed/expired/forged tokens, user isolation, concurrency/overdraft/idempotency, independent manual approval, immutable audit, local HTTP supplier dropped connection and fresh-process no-retry, S3 request stubs, exact access expiry and ranges, and real uvicorn HTTP entrypoint. Existing staging suite: 9 passed. No real Supabase tenant, R2 bucket or paid supplier was contacted. Rate limiting, malware scanning for evidence, remote session revocation propagation, object lifecycle deletion and production monitoring remain deployment work.


Migration `0003` rejects an approved topup unless `evidence_state='clean'` and a completed generation unless `object_key` is set. Approval refuses `pending_scan` and `rejected` evidence. Completed reconciliation refuses a job with no private audio object. Neither check contacts a live supplier or payment processor.

Exactly-once remote execution cannot be guaranteed across an unknown HTTP POST result; uncertain jobs are never automatically retried.
